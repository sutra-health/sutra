# SUTRA capability map

This document maps each SUTRA commitment to a product capability, a user surface, an implementation boundary and a delivery stage. It is the traceability record for how SUTRA is described in public. A commitment listed here is not evidence that the capability already works; the stage label says how far it has been built. See [Delivery scope](./DELIVERY_SCOPE.md) for the full stage definitions.

## Delivery labels

- **Reference**: works end to end with synthetic data in the reference implementation in this repository.
- **Pilot**: intended for a supervised 90-day deployment after site review, security review and clinical approval.
- **Roadmap**: a product direction, not part of any current claim.
- **Illustrative**: a mockup or explanatory view that must be labelled as sample data.

## System boundary

SUTRA is a care follow-through layer. The hospital system remains authoritative for patient identity and clinical records. The hospital scheduler remains authoritative for slot availability and confirmed bookings. SUTRA owns versioned, clinician-signed care steps, contact consent, delivery state, evidence references, operational exceptions and its append-only care-event ledger.

The integration architecture is vendor-neutral. Adapters implement SUTRA's Go/protobuf adapter contract. OpenMRS Mini is the reference adapter, not a dependency of the SUTRA core and not a claim of universal EHR compatibility.

Terms used below: an **EHR** is an electronic health record; **ABDM** is the Ayushman Bharat Digital Mission, India's national digital health framework, and an **ABHA** is a patient's ABDM health account; **OCR** is optical character recognition; **STT** is speech-to-text; **MCP** is the Model Context Protocol, an open protocol that lets AI tools inspect external systems; **OPD** is the outpatient department.

## Acceptance rules for every capability

1. Every clinical or operational event stores the hospital, patient reference, episode, pathway version, actor, source, timestamp, correlation ID and evidence reference where applicable.
2. Every adapter declares which external system is authoritative for each resource and operation.
3. SUTRA never tells a family that an appointment is booked until the source scheduler confirms a booked-equivalent status and external identifier.
4. OCR and speech outputs are drafts. Dates, numbers, names, medicines and negation require explicit confirmation by the appropriate person.
5. Models may extract or suggest a topic. Deterministic rules and authorized people control routing, deadlines, closure, escalation and all clinical decisions.
6. Symptom, medicine, low-confidence and unknown messages default to human review.
7. Emergency signposting is always immediately available. It is a fixed instruction, not an assessment.
8. Only synthetic or fully anonymised data may be used in the reference implementation and the demonstration environment.
9. Reference, illustrative, pilot and roadmap capabilities must remain visibly distinguishable in the user interface, documentation and any demonstration.
